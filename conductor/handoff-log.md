### Measured size and speed (M4 Mac mini, `export()` only, after the IR is built)

| scale | views / fields / findings | bytes | render |
|---|---|---|---|
| enterprise_mono | 20 / 196 / 27 | 1,577,299 | 0.06 s |
| large (20 copies) | 400 / 3,920 / 540 | 14,774,679 | 2.76 s |
| very large (50 copies) | 1,000 / 9,800 / 1,350 | 35,734,611 | 16.07 s |

Caps asserted in `test_export_size_and_render_time_at_scale`: large <= 22.2 MB / 12.5 s, very large <= 53.6 MB / 72 s. Bytes: 1.5x measured. Time: 1.5x the CI runner (ubuntu-latest, Python 3.11), which measured very large at 48.3 s (3.0x the mini; the first cap, 3x the mini, failed there by 0.3 s), large estimated at 8.3 s by the same factor. Very large at 50 copies: findings templates 7.3 MB (status x category x page combos, rows repeat ~4x), object/finding pages 19.6 MB, embedded data 7.2 MB (index 2.9, graph 2.5, aliases 1.1, comments 0.7). In Chrome the 20-copy file shows its first page 209 ms after navigation and ⌘K searches 5,880 items.

**Very large is past ~25 MB and ~10 s, so: proposal, not built — `--export-scope`.** `--export-scope findings` (the triage tabs, finding pages and the objects those findings sit on, plus their one-hop neighbours) would cut object pages to the ones a reviewer opens from a finding; `--export-scope model=<glob>` would export one model family. Either keeps the graph data whole or prunes it to the exported objects. A cheaper, scope-free saving: render the Findings list once per status tab and filter category client-side (about 5 MB at 50 copies), at the cost of byte identity for chip URLs.

Render time is dominated by per-page whole-graph scans that predate this slice (they also slow the live server per request at scale): `mcp/tools._field_count_for_view` (scans every node id; 5.1 of 10.6 profiled seconds at 20 copies, called through `strata_explore_deps` and `build_explore_slice`), `l1/enrich.direct_view_consumers` / `view_consumer_map`, `identifiers.explores_by_key` / `_explore_pairs`, `strata_impact`. Indexing them once per graph would make the export (and the live pages) linear. Not filed as an issue (the brief forbids creating issues): for the head to file.

### Decisions

- **Findings: separate templates, not client-side filtering.** Every status tab x category chip x page is pre-rendered by the server code, so each chip and tab link in the file opens the server's own page (byte-identical, no second filter implementation in JS). Cost: rows repeat about 4x (measured above). The free-text `q` filter is the one Findings query not pre-rendered (unbounded); in the export it opens ⌘K with the text.
- **Graph: one focused page, re-pointed.** One template per graph node (and per hop state) would be 3.2 KB x nodes x up to 8 states; the brief asks for client-side neighbourhoods anyway. So the file holds the picker and one focused page (byte-identical); any other focus/state is that page with the focus label, links and aria-current set from the embedded node (its default route comes from Python, so `links.graph_path` quoting is never repeated in JS) and the server's ring list removed (graph.js draws).
- `c` offline: per-finding lines + `comment_header` composed in JS; a node test pins it to `pr_comment` for single ids, several, duplicates and an unknown id, with and without a workbench base.
- The export's `Workbench` keeps `base_url` (from `--workbench-url` / config), so its PR comments link `<base>#/finding/<id>`.

### Deviations from the brief

- `strata_object` (core, mcp/tools.py) gains an optional `findings_by_node` argument: without it the export took 325 s at 20 copies. Callers that omit it are unchanged.
- View pages on the live server now list their fields too (the export has no field pages; D7 says fields show on view pages).
- `--out` no longer writes the JSON artifacts or serves DIR (`strata outputs` relies on nothing from `--out`; CI calls `strata outputs`). Noted as a 0.2.0 compatibility change in the CHANGELOG.
- The export's only focused-graph template is the first graph node's page; other foci are client-drawn (above), so "every server route byte-identical" holds for every template in the file, and graph foci other than the frame are the frame re-pointed.
- `--port` with `--out` is now a usage error (the export binds nothing).
